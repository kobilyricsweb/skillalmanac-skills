Required inputs are request types, the complete candidate field list, routing or downstream needs, accepted format rules, optionality rules, validation sources, available validation results, and the rejection or incomplete-case policy. Identify fields that are explicitly conditional, optional, prohibited, or not applicable by type. A validation source names how a value should be checked; it does not establish that validation succeeded. If a required validation result is absent, classify completeness as unresolved rather than complete. If a rule references an unnamed downstream need or validation source, preserve the reference and mark its details missing. Missing request types or field definitions prevent reliable requiredness decisions and must be reported. When candidate fields are supplied but no request type is declared, retain one record per candidate field with an empty request_type_rules array, record the missing request types in gaps, and keep completeness unresolved.

Return one field record per candidate field. Each field record must contain one request-type rule for every declared request type; this is zero rules when no request type is declared. A request-type rule states request_type, applicability, requiredness, absent_or_invalid_handling, and rule_trace. Use unspecified when no supplied rule classifies that field for that request type. Do not collapse different type-specific states into one field-level requiredness value.

Shared field properties are purpose, accepted_format, validation_source, and validation_result_status. When a property varies by request type, set its field-level value to a concise statement that it varies and include the applicable optional override—purpose, accepted_format, validation_source, or validation_result_status—in each affected request-type rule. A type-specific property, when present, overrides the corresponding field-level property only for that request type. Omit the optional override when the shared field-level value applies unchanged.

Include completeness examples and unresolved conflicts. Never infer mandatory status from convenience, common practice, job title, or field name.
