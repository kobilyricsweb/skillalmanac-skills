## Accessibility audit: signup.html (Create your account page)
Standard: WCAG 2.2 level AA. Method: static checker (run, 16 FAIL and 9 WARN, every finding confirmed in source) and manual source review in the order of the skill's manual checklist.
This is not a conformance claim. signup.html was not changed.

Lines refer to signup.html. Where a checker finding was wrong or incomplete, the row says so.

### Checked, no failure found
These areas were read in source and no failure was found in them. This is not a claim that they pass.
- Page title (2.4.2): "Create your account | Larkspur Payroll" is descriptive.
- Structure (1.3.1): one h1, one main landmark. The heading skip and the radio grouping are listed above.
- Skip link (2.4.1): only one link precedes main (the logo), so no bypass link is required.
- Single-key shortcuts (2.1.4): none found.
- Context change on focus or input (3.2.1, 3.2.2): no focus or value change navigates or submits. The meter and radio buttons only change styles or selection.
- Redundant entry (3.3.7): no repeated request for information in one process.
- Consistent help (3.2.6): no help link or contact block in the page.
- Dragging (2.5.7): no drag interaction.
- Motion, autoplay and flashing (2.2.2, 2.3.1, 2.3.3): no animation, video or flashing content in source.
- Reflow at 320 CSS px (1.4.10): inputs are width 100%, container max-width 480px, padding 16px. No fixed width that forces horizontal scroll was found. The 64px topbar contains only the logo.
- Text spacing and resize (1.4.12, 1.4.4): text containers have no fixed heights. The only fixed height is the topbar.
- Body text contrast (1.4.3): #222 on white (about 16:1) and the error text #d00 on white (about 5.7:1) pass.
- Error colour (1.4.1): the email error has text, so the red border is not the only signal (but see row 16 for association).

### Not tested
- Real screen readers (NVDA, JAWS, VoiceOver, TalkBack) and their announcements of names, roles and states.
- A real keyboard run in a browser: tab order after the tabindex fix, focus visibility on real rendering, and the sticky bar overlap (row 28).
- Rendered contrast of anything over images or gradients (none found in source).
- Server-side error handling after the POST: whether errors come back with focus moved or an error summary is announced. The page has no live region for errors, and this cannot be seen in the static source.
- Behaviour of the CAPTCHA image and any audio alternative, which are not in this file.
- Zoom and reflow in a browser at 320 px and 200% text size, and the phone viewport at real device width.
- User testing with people who use assistive technology.
- Whether /signup/timeout and the form action /signup handle timeouts, errors and re-entry correctly. Those pages are outside this file.

### Totals
7 blocker, 9 serious, 11 moderate, 3 minor (30 findings in total). The static checker reported 16 FAIL and 9 WARN; each was confirmed in source. Row 14 was a WARN that is a confirmed FAIL. Row 19 corrects the checker's autocomplete suggestion for the phone field.
