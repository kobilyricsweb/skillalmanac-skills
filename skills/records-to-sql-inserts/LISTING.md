# records-to-sql-inserts

## One line

Turns a CSV or JSON records file into one `.sql` file holding a CREATE TABLE, inferred column types, and INSERT statements of up to 100 rows each.

## What it does

The script reads one CSV file with a header row, or one JSON file holding an array of flat objects. For each column it looks at the non-empty values and picks BOOLEAN, INTEGER, REAL, DATE or TEXT. Values that look numeric but carry a leading zero, whole numbers too large for 64 bits, and columns with no values at all stay TEXT and are reported as findings, so ZIP-style codes and long identifiers are not silently changed. Text values have each single quote doubled, empty cells become NULL, and table and column names are checked against a fixed identifier pattern and double-quoted. The console output lists the row count, the statement count and one type line per column. The script exits 1 when findings exist and still writes the file. It refuses to overwrite an existing file and never writes to the input path.

## When to use

- A spreadsheet export needs to load into a database table, and you want the CREATE TABLE and INSERT lines in one reviewable file.
- A JSON export of flat objects needs converting on a machine with no database connection.
- You want to see which columns would be typed as DATE or BOOLEAN before writing the DDL by hand.

## When not to use

- The input is larger than 2 MB, contains nested objects, or is not UTF-8 text.
- The target table already exists and must be altered, or rows must go into a live database. The script writes files only.
- You need primary keys, foreign keys or NOT NULL constraints. None are emitted.

## Requirements

Python 3.9 or later, standard library only. No third-party packages, no network access and no database driver. Run it with `python -I` from the skill folder.

The file `sample_records.sql` from the same run:

```sql
-- Generated by records_to_sql.py. Rows: 7.
-- Identifiers are double-quoted (ANSI SQL). MySQL needs ANSI_QUOTES or backticks.
-- BOOLEAN is written as TRUE/FALSE. Older SQLite needs 1/0; MySQL stores BOOLEAN as TINYINT(1).
-- Backslashes are not escaped. MySQL needs NO_BACKSLASH_ESCAPES or edited string literals.
-- No primary key or NOT NULL constraints are emitted. Add them by hand if needed.

CREATE TABLE "sample_records" (
  "id" INTEGER,
  "customer_name" TEXT,
  "signup_date" DATE,
  "balance" REAL,
  "active" BOOLEAN
);

INSERT INTO "sample_records" ("id", "customer_name", "signup_date", "balance", "active") VALUES
  (1, 'Ann O''Neil', '2024-01-15', 10.50, TRUE),
  (2, 'Bo Chen', '2024-02-03', 0, FALSE),
  (3, 'Dee Park', '2024-02-29', 25.75, TRUE),
  (4, 'Eve, the "Great"', '2024-03-10', NULL, FALSE),
  (5, 'Finn Ruiz', '2024-04-01', 99.99, TRUE),
  (6, 'Gia Lund', '2024-05-18', -3.2, FALSE),
  (7, 'Hal Ito', '2024-06-30', 1200, TRUE);
```

## Limits

- Type inference reads only the values present in the file. A column that looks like dates in the sample can hold other values in a later load.
- Backslashes are not escaped, so MySQL string literals containing a backslash need a manual review.
- Dialect differences are listed in the file header but are not rewritten. The SKILL.md dialect table says what to change.
- The 63-character identifier limit is a working value chosen by the script, not a published limit of any database.
- The script does not run the SQL, compare the rows with the source, check that a target database accepts the types, or look for duplicate rows.
- Output is written in one pass. If the disk fills during the write, a partial file can remain and must be deleted before a rerun.
