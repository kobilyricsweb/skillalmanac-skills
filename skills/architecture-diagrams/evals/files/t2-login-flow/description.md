# Login flow, as the team describes it

A user opens the mobile app and taps Sign in. The app sends the email and password to the Auth service. Auth looks the user up in the Users database and checks the password hash. If the user has two-factor turned on, Auth asks the SMS Gateway to send a code, the gateway texts the user, and the user types the code into the app, which sends it back to Auth. When everything checks out Auth asks the Token Service for a session token, writes an audit entry to the Audit Log, and returns the token to the app. The app then calls the Profile service with the token to load the profile, and Profile asks the Cache first and the Users database on a miss. If the password is wrong, Auth increments a counter in the Rate Limiter and returns an error; after five failures the Rate Limiter blocks the account and Auth sends an email through the Mail Service. Analytics receives an event on every login attempt from the app.
