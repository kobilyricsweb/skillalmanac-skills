Required fields are: complete source-code list; complete target-code list; definitions or descriptions; approved mapping notes; and any effective-date, version, jurisdiction, or scope constraints. Identify the direction of mapping and whether one-to-many or many-to-one relationships are permitted. If a definition, note, required date, or scope is missing or contradictory, mark the affected relationship unresolved. A date is required only when the input or governing mapping requirements say so; otherwise preserve the absence of a date constraint without inventing one.

The output must include source code, target code, mapping type, rationale source, applicable constraints, status, and unresolved entries. Every supplied code must be accounted for without silently treating absence as a match or a confirmed no-map determination. Use blocked when missing evidence prevents determining a code’s relationship. Use unmapped only when supplied authority explicitly establishes that no target applies. Similar labels do not establish equivalence. Do not recode records, invent targets, or generalize a mapping beyond the supplied scope.
