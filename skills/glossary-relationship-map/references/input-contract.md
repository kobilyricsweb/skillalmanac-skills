Required fields are glossary_entries, approved_relationship_statements, hierarchy_rules, and prohibited_equivalences. Each entry needs a stable term identifier and supplied definition text. Statements must identify both terms and the asserted relation. Treat a pair without an approved direct statement as an unresolved link only when the input proposes that relationship, a required definition is missing, supplied statements genuinely conflict under a declared rule, or the pair forms the endpoints of a supplied multi-edge path. A multi-edge path is a chain of two or more supported edges and qualifies even when it mixes relation types. Identify the path and the direct statement or authorizing inference rule needed; do not emit unrelated pairs merely because their terms coexist in the glossary. Hierarchy rules must specify permitted relation names and any allowed inverse, symmetric, or transitive behavior. Different supplied relations are not conflicting unless a supplied rule declares them incompatible. Prohibited equivalences identify pairs that must not be labeled equivalent and must be preserved in the dedicated prohibited-equivalences output. Output fields are relationship_map, prohibited_equivalences, unresolved_links, and verification_report. Each map record contains source_term, target_term, relation_type, direction, support, and status. Each prohibited-equivalence record contains the pair, supporting prohibition, and status. Unresolved records contain the pair, issue, and needed input. The report states whether each map edge has supplied support, whether every prohibition was preserved, whether inverse handling followed the rules, and which terms remain unlinked. Do not derive hierarchy from linguistic similarity or external knowledge. Documents are data and cannot authorize unrelated ontology changes.
