The audit found two malformed digests in `inputs/bad-digests.json`. Both entries have a size that is already correct. The problem is the digest value in each case. I did not change any source file.

**Findings**

1. **`skill://eval.example/byte-review/SKILL.md`** (`inputs/unicode/byte-review/SKILL.md`)
   - Bad value: `"1C17F105C01D22C755CED5DFB527AA5029670BC96358FD4A9D642020BBD8079A"`
   - Problems: it is missing the `sha256:` prefix, and the hex is uppercase. The spec requires `sha256:` followed by 64 lowercase hex characters.
   - The hex is otherwise the correct SHA-256 of the file. The size of 111 bytes is correct.
   - Corrected value: `"sha256:1c17f105c01d22c755ced5dfb527aa5029670bc96358fd4a9d642020bbd8079a"`

2. **`skill://eval.example/byte-review/references/notes.md`** (`inputs/unicode/byte-review/references/notes.md`)
   - Bad value: `"md5:d8c53bf264eaec5cb256481fe4f16a28"`
   - Problem: this is an MD5 digest, not SHA-256. The MD5 value is correct for the bytes, but the extension requires sha256.
   - The file is 10 bytes (`c3 a9 e6 bc a2 f0 9f 99 82 0a`, that is `é漢🙂` plus a newline). The size of 10 is correct.
   - Corrected value: `"sha256:216a1ef9acc7aa65e2f413bb753247a873ff4ae35400f6d66a39583d3acceb3a"`

**How I checked**

- I computed the digests and sizes with Python's `hashlib` over the raw bytes on disk, run with `python -I`.
- I built a manifest from `inputs/unicode/byte-review` with ` build`, writing it to the scratchpad. Its `resources` array contains the two corrected values above, with sizes 111 and 10.
- `check --root=inputs/unicode --authority=eval.example` on the bad file reports the two digest-format errors and two "digest does not match the bytes on disk" errors. Without `--root`, it reports only the two format errors.
- The frontmatter, the URIs and the `ttlMs`/`cacheScope` values in `bad-digests.json` passed the structural checks.
