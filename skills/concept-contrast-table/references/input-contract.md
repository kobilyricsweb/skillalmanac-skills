Required fields:
- Concept names and definitions.
- Approved examples and nonexamples for each concept.
- Known learner confusions.
- Learner level and any required vocabulary limits.

The source must identify which examples and nonexamples belong to which concept. If a field is missing, say what cannot be established and produce only a partial comparison when useful. If definitions or labels conflict, preserve both versions, flag the conflict, and do not silently reconcile them.

Interpret evidence directionally. An approved example supports its named concept. A nonexample establishes only that the case is not the named concept; it does not classify the case as another concept. For each boundary case, test every concept against its own supplied definition or approved evidence. Use a null classification when no concept is independently established, and do not derive one definition as the converse of another.

Output fields:
- Learner-level orientation.
- Defining features and non-features for each concept.
- Boundary cases and recognition cues.
- One discriminating question only when supplied evidence establishes the distinction and rules out relevant both-concept and neither-concept cases; otherwise null, with the unsupported exclusivity or exhaustiveness recorded in unresolved ambiguities.
- Evidence and unresolved-ambiguity note.

Use only supplied distinctions. Do not add exceptions, outside examples, inferred converses, or exhaustive classification rules. Keep the contrast focused on decisions the learner must make.
