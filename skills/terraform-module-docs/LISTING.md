# terraform-module-docs

## One line

Generates a Markdown reference page for one Terraform module's variables, outputs, providers and resource counts, and flags variables that lack a description or a type.

## What it does

The script reads the `.tf` files sitting directly inside one module directory. It strips comments, matches braces to find each `variable`, `output` and `required_providers` entry, and reads the attributes a reference page needs: type, default, description, source and version. It counts `resource` blocks by type, so a reader can see at a glance what the module creates. The result is one new Markdown file with five sections: Variables, Outputs, Providers, Resources and Findings. Default values of variables whose names look like secrets, such as password, token or api_key, are replaced with a redaction marker, so the page can be shared without exposing them. The script never overwrites a file. It stops with exit code 2 if the output path already exists, and it never writes next to its inputs. A single JSON summary line gives the same counts and the finding list, so a pipeline can react without parsing Markdown. Exit code 1 means the page was written and at least one variable needs attention.

## When to use

Use it when a module's README no longer matches its variables after a refactor, when a reviewer asks for a flat list of inputs and outputs, or when a module is about to be tagged and its variables should be checked for missing descriptions or types first. It is a quick, repeatable check: the same folder always gives the same page.

## When not to use

Do not use it for modules written as `.tf.json`, for reading values from a plan, for following module calls, or for evaluating expressions. It is not a policy engine and does not judge whether a description is good. It does not edit module source files; it writes one new Markdown file and nothing else.

## Requirements

Python 3.9 or later with the standard library only. No network access and no subprocess calls. The input is a directory that holds at least one `.tf` file. Each file must be 2 MB or smaller and valid UTF-8.

## Example

The run below used the smoke module built by the helper in this package. The first line is the JSON summary the script printed to stdout. The Markdown after it is the file the script wrote. The script exited with code 1 because one variable has no description.

```
{"status": "findings", "files": 3, "variables": 4, "outputs": 2, "providers": 2, "resources": 3, "resource_types": {"aws_s3_bucket": 1, "aws_s3_bucket_versioning": 1, "random_id": 1}, "findings": [{"code": "VAR_NO_DESCRIPTION", "name": "enable_versioning", "file": "variables.tf"}]}
```

```markdown
# Module tfsmoke

Generated by scripts/tf_docs.py from 3 .tf file(s). Regular-expression parsing: compare with the source before publishing.

## Variables

| Name | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| `region` | `string` | `"us-east-1"` | no | AWS region for the bucket. Use "us-east-1" for the default. |
| `bucket_name` | `string` | - | yes | Name of the S3 bucket to create. |
| `admin_password` | `string` | `(redacted)` | no | Initial admin password. |
| `enable_versioning` | `bool` | `true` | no | - |

## Outputs

| Name | Description |
| --- | --- |
| `bucket_arn` | ARN of the bucket. |
| `bucket_id` | Name (ID) of the bucket. |

## Providers

| Name | Source | Version |
| --- | --- | --- |
| `aws` | `hashicorp/aws` | `~> 5.0` |
| `random` | `hashicorp/random` | `-` |

## Resources

| Type | Count |
| --- | --- |
| `aws_s3_bucket` | 1 |
| `aws_s3_bucket_versioning` | 1 |
| `random_id` | 1 |

## Findings

- VAR_NO_DESCRIPTION: variable `enable_versioning` in `variables.tf` has no description attribute.
```

## Limits

- Regular-expression parsing, not an HCL parser. A heredoc description counts as present, but the page shows only the opening marker.
- Expressions are not evaluated. A default built from a local value or a function appears exactly as written.
- Provider versions are shown as written. They are not checked against any registry or lock file.
- `data` blocks are not counted as resources. `validation` and `precondition` blocks are not shown.
- Redaction matches variable names only. A secret stored in a default under a neutral name is printed as written.
- The script does not check that the page is accurate, that the module plans or applies, or that the descriptions are useful.
