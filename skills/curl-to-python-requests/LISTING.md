# One line

Turns a saved curl command into a Python requests snippet, with credentials masked and nothing sent.

## What it does

The skill runs a small standard-library Python script that reads one curl command from a text file. The command is split with shlex, so the shell never runs it and the URL is never called. The script reads the method, headers, body, form fields, basic-auth user, query string and a set of common flags, then prints a requests call that reproduces them. Credentials are replaced by placeholders: the basic-auth pair becomes `<USER>` and `<PASSWORD>`, and values under keys such as password, token or api_key, or under headers such as Authorization and Cookie, become `<REDACTED>`. Flags the script cannot translate, such as output files, proxies and certificate options, are listed as findings inside the snippet as comment lines, and the exit code shows whether any were found. The translation follows curl's defaults where they differ from requests: a curl call without -L does not follow redirects, so the snippet sets allow_redirects to False, and a body without -X makes the method POST.

## When to use

Use it when someone pastes a curl line from API documentation, a support ticket or browser developer tools and wants the same request in Python. It suits a short command with one URL, a few headers, a JSON or form body, and basic auth. The output is a starting point the reader can review line by line before running it.

## When not to use

Do not use it to run the request, check that an endpoint responds, or debug a failing call on the server side. It does not handle Windows cmd or PowerShell quoting, ANSI-C $'...' strings, multipart file uploads, cookie jar files or curl config files. Do not use it to translate code in other languages, or to convert a whole shell script with several commands.

## Requirements

Python 3.9 or newer, standard library only. No network access, no subprocess and no third-party packages. The input is one UTF-8 text file of at most 2 MB, written in POSIX shell quoting. The skill itself needs only a text-capable agent to read the script's output and fill the reply template.

## Example

Command, from a fixture saved as a text file:

```
curl -X POST 'https://api.example.com/v1/orders?region=us' \
  -H 'Accept: application/json' \
  -H 'X-Client: smoke-test' \
  -u 'demo_user:s3cret-pass' \
  --json '{"item": "widget", "qty": 2, "password": "hunter2"}'
```

Output of `python -I scripts/curl_to_py.py <input-file>`, exit code 0:

```python
# Generated by curl_to_py.py from a curl command. Nothing was sent.
# Masked values: basic auth, password
import requests

url = "https://api.example.com/v1/orders"
params = {
    "region": "us",
}
headers = {
    "Accept": "application/json",
    "X-Client": "smoke-test",
    "Content-Type": "application/json",
}
json_body = {
    "item": "widget",
    "qty": 2,
    "password": "<REDACTED>",
}
response = requests.post(
    url,
    params=params,
    headers=headers,
    auth=("<USER>", "<PASSWORD>"),
    json=json_body,
    allow_redirects=False,
)
print(response.status_code)
```

## Limits

The script does not verify that the snippet matches curl's behavior on the wire. It does not compare responses, and it does not run the Python code. Masking works on key and header names only: a secret inside a free-form body, or a token placed in an unusual key, is printed as written. Values from -d @file, -F field=@file and -b cookie files are not read and are reported as findings. URL fragments are dropped without a finding. Percent-encoded path segments are kept as written. The script treats -G, -L, -k and -I as described above and ignores quiet and compression flags, which have no requests equivalent that changes the result.
