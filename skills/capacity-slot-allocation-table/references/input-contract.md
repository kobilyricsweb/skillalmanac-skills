Required input fields are: task records with unique name, duration, and eligible resources; resource records; time slots with resource, start, and end; and explicit priority rules. State whether tasks may be split, whether simultaneous work is allowed, and any fixed assignments or blackout periods. If a field is absent, mark the affected allocation unknown and request clarification; do not infer capacity or priorities. A missing priority rule does not make a singleton noncompetitive allocation unknown when no alternative task or placement is being selected. Conflicts between supplied rules must be listed before allocation and resolved only by an explicit precedence rule. Output fields are: assumptions and input conflicts; allocation table; unallocated tasks with reasons; unresolved tasks with missing inputs; unused slots; feasibility status; and verification notes. Durations must remain unchanged, resource overlaps are prohibited unless explicitly allowed, and no optimality, staffing, or completion guarantee may be claimed. A partial result is acceptable when infeasibility is explicit.
